## 六、控制语句与其他规范

### 【强制】switch 块内每个 case 必须通过 continue/break/return 终止，或注释说明继续执行到哪个 case；必须包含 default 语句并放在最后，即使没有任何代码

### 【强制】当 switch 括号内变量类型为 String 且为外部参数时，必须先进行 null 判断（否则抛 NPE）

### 【强制】在 if/else/for/while/do 语句中必须使用大括号，即使只有一行代码

### 【强制】三目运算符高度注意自动拆箱导致的 NPE：表达式 1 或 2 有一个是原始类型、或两者类型不一致时，会强制拆箱升级成表示范围更大的类型

反例：`Integer c = null; Integer result = (flag ? a*b : c);` —— a*b 是 int，c 被强制拆箱抛 NPE。

### 【强制】高并发场景避免用"等于"判断作为中断或退出条件，用大于或小于的区间判断代替

反例：判断剩余奖品数量等于 0 时终止发奖，并发处理错误使数量变负数后活动无法终止。

### 【推荐】表达异常分支时少用 if-else，可用卫语句改写；if()...else if()...else... 方式请勿超过 3 层，超过时用卫语句、策略模式、状态模式实现

### 【推荐】除 getXxx/isXxx 等常用方法外，不要在条件判断中执行复杂语句，将复杂逻辑结果赋值给有意义的布尔变量名；不要在其它表达式（尤其条件表达式）中插入赋值语句

### 【推荐】避免取反逻辑运算符：用 `if (x < 628)` 而不是 `if (!(x >= 628))`；方法超 10 行时，return/throw 等中断逻辑的右大括号后加一个空行

### 【推荐】循环体内的定义对象、定义变量、获取数据库连接、不必要的 try-catch 尽量移至循环体外；公开接口必须做入参保护，尤其是批量操作接口

### 【参考】需要参数校验的情形：调用频次低的方法、执行时间开销大的方法、极高稳定性和可用性要求的方法、对外 RPC/API/HTTP 开放接口、敏感权限入口。可省略：极可能被循环调用的方法、底层高频方法（DAO 层）、private 且仅自己代码调用的方法

### 【强制】正则表达式利用预编译功能，不要在方法体内定义 Pattern

反例：`Pattern pattern = Pattern.compile("规则");` 出现在方法体内。

### 【强制】避免用 Apache Beanutils 做属性 copy（性能差），可用 Spring BeanUtils、Cglib BeanCopier（注意均为浅拷贝）

### 【强制】Math.random() 返回 [0,1) 的 double，注意除零异常；获取整数随机数直接用 Random 的 nextInt/nextLong

### 【推荐】任何数据结构的构造或初始化都应指定大小，避免无限增长吃光内存；及时清理不再使用的代码段或配置信息，暂时注释的代码用三个斜杠 /// 说明理由
