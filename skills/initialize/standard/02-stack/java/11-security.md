## 十一、安全规范

### 【强制】隶属于用户个人的页面或功能必须进行权限控制校验，防止缺少水平权限校验导致越权访问、修改、删除他人数据

正例场景：防止查看他人的私信内容。

### 【强制】用户敏感数据禁止直接展示，必须对展示数据脱敏

正例：中国大陆手机号显示 `139****1219`，隐藏中间 4 位。

### 【强制】用户输入的 SQL 参数严格使用参数绑定或 METADATA 字段值限定，防止 SQL 注入，禁止字符串拼接 SQL 访问数据库

反例：危险字符 `#` `--` 未转义，导致数据库更新时 where 后信息被注释掉，对全库更新。

### 【强制】用户请求传入的任何参数必须做有效性验证

说明：忽略参数校验可能导致 page size 过大内存溢出、恶意 order by 慢查询、缓存击穿、SSRF、任意重定向、SQL/Shell/反序列化注入、正则输入源串拒绝服务 ReDoS（特殊构造字符串使某些正则进入死循环）。

### 【强制】禁止向 HTML 页面输出未经安全过滤或未正确转义的用户数据（XSS）

### 【强制】表单、AJAX 提交必须执行 CSRF 安全验证

说明：CSRF 跨站请求伪造下，攻击者构造好 URL，受害者一访问，后台即在用户不知情时修改数据库中的用户参数。

### 【强制】URL 外部重定向传入的目标地址必须执行白名单过滤

### 【强制】使用平台资源（短信、邮件、电话、下单、支付）必须实现正确的防重放机制：数量限制、疲劳度控制、验证码校验，避免被滥刷导致资损

### 【推荐】发帖、评论、发送即时消息等用户生成内容（UGC）场景必须实现防刷、文本内容违禁词过滤等风控策略
