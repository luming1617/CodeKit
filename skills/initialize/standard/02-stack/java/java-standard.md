# 团队 Java 开发规范

版本：1.1｜依据：《Java 开发手册》嵩山版 1.7.0（2020-08-03）

## 0. 适用范围与执行方式

- 适用于团队 Java 服务端项目；MySQL、MyBatis、Spring 条款仅在采用相应技术时生效。API 行为以项目版本为准。
- 除标注【建议】外，条款均为合并要求；必须项的例外须记录原因、影响、替代措施及项目负责人确认结果；建议项偏离时说明理由。
- 新增代码全面执行，修改代码覆盖变更及直接影响范围；存量问题逐步治理。生成及第三方代码单独检查。
- 本文经团队化取舍与补充；未覆盖内容经评审统一规则，本文未收录的原手册条款不自动构成额外强制要求。

## 1. 命名、常量与格式

1. 命名表意。使用英文或通用缩写，禁止中文、拼音混写和随意缩写，约定的品牌名、地域名除外。业务标识符禁止歧视性用语及首尾下划线、美元符号。
2. 统一风格。类名 `UpperCamelCase`；方法、参数、变量 `lowerCamelCase`；常量 `UPPER_SNAKE_CASE`；包名全小写、按业务组织。常量名包含单位和业务语义，如 `ORDER_TIMEOUT_SECONDS`。
3. 名称体现职责。持久化对象 `DO`、传输对象 `DTO`、展示对象 `VO`、查询条件 `Query`；异常类以 `Exception` 结尾，单元测试以 `Test` 结尾。已有 `Entity/Request/Response` 体系沿用，禁止混用。
4. 布尔属性不加 `is` 前缀。例如属性为 `deleted`；不得同时定义同一属性的 `isDeleted()` 与 `getDeleted()`。数据库字段 `is_deleted` 与 Java 属性显式映射；使用代码生成工具时检查生成的访问器和序列化结果。
5. 业务常量集中到所属模块。状态码、阈值、缓存键前缀禁止散落为字面量；禁止建立包揽所有业务的常量类。表示数量起点的 `0`、循环步长的 `1` 等自明字面量无需机械提取。`long` 字面量后缀使用 `L`。
6. 统一格式。UTF-8、LF、4 个空格缩进，禁止 Tab；每行最多 120 字符，不可拆分的链接等除外。非空代码块左大括号不另起一行，控制语句均加大括号；二元及三元运算符两侧、参数逗号后加空格；使用仓库格式配置，不重排无关代码。
7. 【建议】控制复杂度。单方法不超过 80 行（不含注释），条件嵌套不超过 3 层。超限按职责拆分，不机械凑行数。

## 2. 对象设计与空值契约

1. 职责单一。构造器仅负责注入、校验和建立有效状态，不执行远程调用或数据库业务；getter/setter 不隐藏查询、写库等副作用。成员可见性最小化；静态成员通过类名访问；覆写方法加 `@Override`。
2. 区分缺失与默认值。用包装类型表达“未提供”，不以 `0/false` 掩盖缺失。DTO/DO 不设置会误参与更新的默认业务值；确有协议默认值时，在文档中明确并在输入转换阶段应用。
3. 约定查询结果。列表无结果返回空集合；单对象未找到时，在 `null`、`Optional`、业务异常中选择一种并写入接口契约。查询失败不得返回空集合、空对象或默认值伪装成成功。
4. 防止空指针。拆箱、链式调用、集合取值、远程返回值使用前保证非空。集合非空不代表元素非空；三目表达式可能触发拆箱，不能只检查赋值目标是否为包装类型。
5. 区分值与身份比较。字符串和整型包装类按值比较使用 `equals` 或 `Objects.equals`；枚举可使用 `==`。覆写 `equals` 时同时覆写 `hashCode`；作为哈希键或哈希集合元素后，不得修改参与相等性和哈希计算的字段。
6. 明确复制和输出行为。浅拷贝不会复制嵌套可变对象，需要隔离时显式复制；`toString()` 不作为序列化协议。自动生成的 `toString/equals/hashCode` 必须检查敏感字段、循环引用及不必要的关联对象访问。
7. 【建议】优先组合和不可变对象。固定状态集合使用枚举，跨系统传输使用稳定编码并约定未知编码的处理；不要依赖枚举序号。

## 3. 集合、泛型与控制语句

1. 使用泛型。禁止裸类型和未验证的强转。`? extends T` 主要用于读取，`? super T` 用于写入 `T`，后者读取结果只能按 `Object` 保证类型；不得用强转掩盖类型设计问题。
2. 明确集合契约。判断空集合用 `isEmpty()`；返回值注明是否可修改、是否允许空元素及是否有顺序。需要稳定顺序时选择有序实现或显式排序，不依赖 `HashMap` 的遍历顺序。
3. 正确增删。普通集合增强 `for` 遍历时，禁止直接增删原集合；删除使用迭代器或 `removeIf`。并发访问遵循容器约定，不得仅给某个迭代器加锁就认为整个集合安全。
4. 识别视图。`Arrays.asList` 不支持增删，但可替换元素；`subList`、Map 的键值集合通常与原集合关联。独立列表使用 `new ArrayList<>(source)`；注意这仍是元素引用的浅拷贝。
5. 处理转换边界。数组转换使用带类型的 `toArray`；`Collectors.toMap` 显式处理重复键和空值，合并策略必须符合业务，不能默认“保留最后一个”而静默丢弃重要记录。
6. 比较器遵守比较契约。满足相等、反向比较及传递性要求；禁止使用可能溢出的相减结果，优先 `Integer.compare`、`Long.compare` 或 `Comparator.comparing`；可空字段明确空值排序位置。
7. 分支完整。传统 `switch` 的贯穿执行必须注释，未匹配值有明确处理。外部可空输入先校验；未知业务状态不能默认为成功。复杂条件提取有含义的布尔变量，禁止在条件中隐藏赋值或重要副作用。
8. 【建议】避免重复计算。循环中重复拼接字符串使用 `StringBuilder`；重复正则预编译；集合预估容量，批量操作分批执行；初始容量不等于大小上限。

## 4. 数值、金额与时间

1. 金额精确表示。同一字段跨层统一币种、单位；采用最小货币单位的整数，或约定精度的 `BigDecimal/DECIMAL`，禁止 `float/double`。币种、精度或单位不同时显式转换。
2. 明确舍入。精确十进制值从字符串或整数构造，禁止 `new BigDecimal(double)`；已有浮点值转为 `BigDecimal` 不能恢复此前丢失的精度。除法、税费及折扣计算明确保留位数、舍入模式和舍入时点。
3. 正确比较和运算。`BigDecimal` 按数值比较用 `compareTo`；仅在确需同时比较数值和 scale 时使用 `equals`。非精确浮点计算按业务确定误差容限；涉及数量、时间换算或金额累计时检查溢出范围和除数为零。
4. 时间类型匹配语义。推荐使用 `java.time`：日期用 `LocalDate`，绝对时间点用 `Instant`；地区日历使用带时区类型。`LocalDateTime` 不含时区，禁止不说明时区就将其当成绝对时间传输或比较。
5. 时间契约完整。接口明确时间格式、时区及时间戳单位；普通日期不用周序年 `YYYY`，区分月份 `MM`、分钟 `mm`、24 小时制 `HH`。禁止无同步共享 `SimpleDateFormat`。
6. 按日历计算期限。一年不固定为 365 天，一个月不固定为 30 天；月底、闰日和夏令时的处理写入业务规则。统计进程内耗时使用单调时间源，避免系统时钟调整影响；测试通过可替换时钟固定时间。

## 5. 并发、异步与资源

1. 执行器统一管理。业务代码使用统一管理的平台线程池；线程池明确核心线程数、最大线程数、队列容量、空闲时间、拒绝策略及名称。禁止直接使用具有无界队列或无限扩张线程数风险的默认工厂配置；关键任务不能静默丢弃。
2. 限制资源使用。任务提交、外部调用和批处理有并发上限；耗时不同的任务按需要隔离。禁止在同一受限线程池内提交子任务后无限等待，避免线程饥饿。虚拟线程另行评估并发限额。
3. 共享状态安全。单例不得保存请求私有可变数据；`volatile` 不保证复合操作原子性。并发 Map 的“检查后写入”使用原子方法或额外同步；跨字段、跨记录约束仍需业务层保证。`ConcurrentHashMap` 不接受空键或空值。[依据](https://docs.oracle.com/javase/8/docs/api/java/util/concurrent/ConcurrentHashMap.html)。
4. 锁的范围与顺序明确。成功加锁后立即进入 `try/finally`；`tryLock` 失败不得执行受保护逻辑或解锁。多个资源保持一致加锁顺序，持锁期间避免远程调用；跨进程竞争不得仅使用 JVM 内的锁。
5. 异步失败可观察。处理 `Future/CompletableFuture` 的失败结果，不能只提交任务不检查结果；等待设置超时。捕获 `InterruptedException` 后向上抛出，或恢复中断标记并结束当前任务，不吞掉中断后继续无限等待。
6. 清理上下文。自定义 `ThreadLocal` 在请求或任务结束时清理；异步传递用户、链路、租户信息时显式复制必要数据并在结束时清理。线程池关闭由所有者统一执行，禁止业务代码关闭共享执行器。
7. 关闭自有资源。当前代码负责释放的流、连接、游标使用 `try-with-resources` 或 `finally`；外部传入或框架管理的资源按所有权约定释放，禁止重复关闭共享资源。
8. 定时任务处理异常和重复运行。周期任务记录业务异常并执行约定的继续或终止策略；不能认为使用调度线程池就不会停跑，周期任务抛出异常可能使后续执行被抑制。多实例部署明确是否允许并行执行。[依据](https://docs.oracle.com/javase/8/docs/api/java/util/concurrent/ScheduledExecutorService.html)。

加锁与上下文清理示例（两段属于独立场景）：

```java
lock.lock();
try {
    updateState();
} finally {
    lock.unlock();
}

requestContext.set(context);
try {
    handleRequest();
} finally {
    requestContext.remove();
}
```

## 6. 接口契约与外部调用

1. 契约可实现、可测试。文档注明协议、路径、方法、鉴权、请求及响应结构；字段写明含义、必填性、可空性、范围、长度、单位和示例。新增、修改、删除操作分别定义成功与失败语义。
2. 返回结构稳定。JSON 字段使用小驼峰；列表为空返回 `[]`，对象与数组不能互换。可能超过前端安全整数范围的标识符作为字符串传输；不得因返回值大小不同临时改变同一字段的 JSON 类型。
3. 更新语义明确。区分字段未传、显式 `null`、空字符串及空集合；部分更新不得用未传字段覆盖已有值。需要清空字段时提供明确协议，不得靠对象默认值判断。
4. 服务端限制输入。校验格式、长度、业务范围以及分页大小、批量数量、上传和请求体上限；文档与实际校验一致。分页规定起始页、默认大小、上限和越界行为；排序有稳定依据，必要时增加唯一字段作为次级排序键。
5. 正确使用 HTTP。GET 不产生业务写入副作用；生产对外接口使用 HTTPS，响应声明正确内容类型。HTTP 状态、业务错误码与提示语的映射统一，禁止所有失败均返回成功状态且让调用方猜测。
6. 调用有边界。外部调用设置连接、读取或整体超时；重试仅针对约定的可重试错误，限定次数、间隔及总耗时。写操作超时可能已成功，重试前必须具备幂等或结果查询机制，不能直接认定未执行。
7. 兼容性有计划。不得擅自删除响应字段、改变字段类型或错误码语义；新增枚举值也需评估旧调用方。破坏性变更提供版本、兼容期及迁移方案，废弃接口注明替代方案；调用方不依赖错误提示文本进行业务判断。

## 7. 异常、错误码与日志

1. 异常分类处理。参数不合法、业务拒绝、依赖失败和程序缺陷分开表达；正常可判断的分支不用异常驱动。捕获范围尽量小，只捕获能够处理的类型；禁止空 `catch` 和无依据的“出错返回默认值”。
2. 保留原因。转换异常时保留 `cause`，接口边界统一转为安全响应。禁止在 `finally` 中 `return`；业务代码不得统一捕获 `Throwable` 后继续运行。需要容错的任务边界应明确能恢复的失败类型及停止条件。
3. 错误码稳定。统一登记、语义唯一、发布后不复用；错误码与 HTTP 状态分别管理。沿用手册编码体系时，成功为 `00000`，`A/B/C` 分别表示用户侧、本系统、外部依赖错误；已有体系无需仅为格式更换而迁移。
4. 日志统一。通过 SLF4J 门面记录，使用占位符；异常传入完整异常对象，包含必要业务标识和链路标识。禁止 `System.out/err`、`printStackTrace()`；框架统一输出到标准输出不受此条限制。
5. 避免重复和泄露。同一服务内同一次异常传播，由负责处理的边界记录完整堆栈，下层保留原因向上抛出；独立服务可记录各自失败。禁止记录密码、令牌、密钥及完整敏感请求；禁止直接序列化整个对象作为日志。
6. 级别符合含义。`DEBUG` 用于诊断，`INFO` 用于必要业务事件，`WARN` 用于需关注但可恢复的问题，`ERROR` 用于失败或系统故障；可预期业务拒绝不自动记为 `ERROR`。昂贵的日志参数计算先判断级别。
7. 日志可运营。配置轮转、容量、采集及保留期；保留期按组织批准的数据和审计要求执行。生产诊断日志临时开启时限定范围和时长，禁止长期全量输出；关键错误、任务失败和资源耗尽应有告警。

## 8. 数据库设计、SQL 与 ORM

1. 结构命名一致。表和列使用小写下划线，表名用单数并避免保留字；业务表设置主键、创建时间、更新时间。字段说明业务含义、单位、状态取值和空值含义；唯一索引前缀 `uk_`，普通索引前缀 `idx_`。
2. 类型按范围设计。Java 与数据库类型覆盖全部业务取值；不得默认无符号 `BIGINT` 的全范围都能放入 Java `Long`。精确小数使用 `DECIMAL`；字符串长度有依据，字符集统一使用 `utf8mb4`，排序规则按比较需求统一。
3. 约束明确。必填字段使用适当非空约束，可空字段须有业务语义；不得用空串或零替代所有缺失值。业务唯一性由唯一索引保证，涉及可空列时验证数据库对空值的唯一性规则；禁止只靠先查后插防重复。
4. 索引由查询验证。关键查询使用执行计划和代表性数据验证；联合索引结合过滤、排序及范围条件设计，不机械按区分度排序。检查扫描量、回表、排序和耗时，避免重复索引。
5. 查询范围受控。显式选择字段，禁止业务查询 `SELECT *`；在线列表限制返回数量，大量导出分批或流式处理。深分页、前置通配符搜索和复杂关联须验证性能，不以固定行数阈值代替评估。
6. 参数绑定。MyBatis 值参数使用 `#{}`，动态表名、列名、排序方向由服务端允许列表映射，不能直接接受外部字符串。动态 SQL 在条件集合为空时必须明确返回空结果或拒绝执行，不得意外移除 WHERE 条件。
7. 统计和空值语义正确。统计行数使用 `COUNT(*)`；`COUNT(列)` 不统计该列空值，只有需要该语义时使用。空值判断使用 `IS NULL/IS NOT NULL`，不用 `= NULL`；`SUM` 可能返回空值，是否转零按业务约定。
8. 映射可验证。数据库列与 Java 属性的类型、名称及空值行为明确；非一致命名显式映射。固定结构查询使用具名对象，避免直接返回泛型 Map。更新只包含目标字段，并维护更新时间；批处理检查返回结果。
9. 变更可回退。建表、索引和字段变更纳入版本管理，评估锁表、兼容性和数据迁移。数据订正先查目标及数量，再执行并复核；全表更新、删除或 `TRUNCATE` 走专门变更流程。外键、存储过程、分库分表按架构评审决定，不一律启用或禁止。

## 9. 事务、幂等与一致性

1. 事务围绕业务原子操作。在 Service 层定义事务边界、传播、隔离和超时要求；避免长事务，不把不必要的远程调用包在数据库事务内。不得认为添加注解就已经验证事务生效。
2. 验证代理入口。使用 Spring 代理事务时，通过代理调用事务方法；同类内部调用不会应用被调用方法上的事务配置，也不会按其声明新建事务，但可能继续运行在外层已有事务中。通过集成测试验证实际提交、回滚行为。[依据](https://docs.spring.io/spring-framework/reference/data-access/transaction/declarative/annotations.html)。
3. 回滚条件明确。异常被捕获后仍需回滚，应重新抛出符合回滚规则的异常或显式标记回滚；受检异常是否回滚按项目配置确认。失败返回不等于回滚，需测试回滚。
4. 防止更新丢失。竞争更新使用条件更新、版本号或锁，并检查实际影响行数。乐观锁冲突不能假装成功，重试次数及重新读取策略明确；分布式锁还需处理持有者校验、租约到期和进程失效。
5. 写操作可去重。可能被重试或重复投递的操作定义幂等键、作用范围、保留期限及重复请求的返回行为；幂等键与请求关键内容绑定。不得仅靠按钮禁用、缓存标记或先查后写保证一次生效。
6. 跨资源有补偿。数据库事务不会自动回滚已发送的消息、缓存写入或第三方操作；根据业务采用可靠事件、事务消息、补偿或对账机制。简单“提交后发送”仍可能丢失，关键链路须有恢复渠道。

并发扣减示例：`product_id` 唯一，入参 `quantity > 0`，受影响行数必须为 1；失败时区分记录不存在与库存不足。

```sql
UPDATE product_stock
SET stock = stock - #{quantity}, update_time = CURRENT_TIMESTAMP
WHERE product_id = #{productId} AND stock >= #{quantity};
```

## 10. 安全与敏感数据

1. 认证之外再授权。受保护操作检查操作权限、数据归属和租户边界；用户身份从可信认证上下文取得，不采信客户端提交的用户编号。查询、导出、下载与更新同样执行数据权限校验。
2. 防注入。SQL 使用参数绑定；命令、模板、表达式及反序列化入口禁止直接执行不可信输入。HTML 按输出上下文编码；需要富文本时使用允许列表清洗，不得仅靠替换几个字符。
3. 控制外部地址。重定向目标、服务端抓取地址验证协议、主机和端口；抓取地址还需防止访问非授权内网资源，并检查解析结果及重定向后的目标。禁止把任意用户 URL 直接交给后端请求客户端。
4. 保护凭据。密钥由统一配置或密钥管理渠道注入，不提交仓库或写入日志；权限按最小需要授予。需要本地保存密码时使用组织批准的带盐自适应密码哈希方案，禁止明文或可逆加密存储密码。
5. 防重放和滥用。使用 Cookie 自动携带身份的写操作实施 CSRF 防护；验证码、登录、短信等限制次数和频率，验证码有有效期并限制重复使用。跨域允许列表不能作为身份认证或 CSRF 防护的替代。
6. 上传下载受控。校验文件大小、实际类型及访问权限；服务端生成存储名，防止路径穿越。解压时限制解压后大小、文件数和目标路径；上传内容不得直接进入可执行目录。
7. 最少暴露数据。响应仅包含调用方有权获取且业务需要的字段，展示和日志按需脱敏；错误响应不泄露堆栈、SQL、连接信息和内部路径。敏感操作留存审计记录，明确操作者、对象、动作、时间和结果。

## 11. 工程结构、依赖与设计文档

1. 按职责分层。Controller 处理协议、校验和响应，Service 处理业务与事务，DAO/Repository 处理持久化；Controller 不直接访问数据库，层间禁止循环依赖。外部服务适配集中封装，不把调用细节散落到业务代码。
2. 【建议】按需增加层次。通用业务可下沉到 Manager 或领域组件，但不能为形式要求增加只有转发的方法。优先构造器注入，避免隐藏全局状态。
3. 依赖可重现。统一 JDK、构建工具、插件和依赖版本；生产禁止 `SNAPSHOT`、动态版本及覆盖已发布版本。多模块通过统一版本管理维护依赖；升级后检查传递依赖变化及运行时冲突。
4. 配置可追踪。环境差异通过配置注入；配置注明含义、单位、默认值、范围及是否支持动态更新。新增配置兼顾未配置时的行为，删除配置先确认无调用方依赖；关键阈值不能只写在文档中。
5. 注释表达契约。公开类和接口用 Javadoc 说明职责；公开方法说明参数、返回值、空值、异常和副作用。状态字段、单位及枚举值注明业务意义；注释随代码更新，不重复显而易见的语句。
6. 关键设计留档。状态机注明合法转换和触发条件，跨服务链路注明调用顺序及失败处理，数据设计注明约束及迁移方案。TODO 写明负责人、原因和跟踪事项；交付范围内尚未完成的功能不得仅靠 TODO 说明。

## 12. 测试、评审与发布

1. 测试自动化。单元测试放在 `src/test/java`，使用测试框架断言；用例互不依赖、无执行顺序要求，可重复运行。禁止依靠打印结果人工判断，禁止直接依赖生产资源。
2. 覆盖行为。新增或修改业务覆盖正常、空值、边界、非法输入及失败分支；修复缺陷补回归用例。库存、金额、权限和状态转换等关键约束须有断言，不能只验证“没有抛异常”。
3. 隔离与集成分工。单元测试隔离网络、时间、随机数等不稳定依赖；数据库映射、事务、消息和外部协议通过集成测试验证。测试数据由程序准备并清理，不依赖手工预置或其它用例留下的状态。
4. 验证故障场景。涉及并发或重试时测试竞争、重复提交、超时和部分成功；异步测试设置等待上限，不用任意长时间休眠代替同步。测试执行真实的代理或事务入口，防止绕过框架而误判。
5. 【建议】覆盖率辅助评审。项目在 CI 中定义增量覆盖率门槛及排除项；覆盖率不能替代业务断言，也不能为追求百分比测试无意义代码。核心分支确实无法覆盖时说明原因和替代验证方式。
6. 合并前检查。代码评审通过，编译、统一格式检查、静态检查及相关测试通过；新增严重安全或正确性问题未解决不得合并。评审重点含契约变化、空值、并发、事务、权限和资源边界。
7. 发布可恢复。接口、依赖和数据库变更说明兼容性及回退步骤；发布前准备必要的备份、迁移和校验。发布后检查错误率、延迟、关键任务和业务结果；数据库已变更时确认旧代码仍能运行，不能只回退应用包。
