## 七、API 与前后端交互规范

### 【强制】前后端交互的 API 必须明确协议、域名、路径、请求方法、请求内容、状态码、响应体

- 协议：生产环境必须使用 HTTPS。
- 路径：代表一种资源，只能为名词（推荐复数），不能为动词；不得使用大写，单词分隔统一用下划线；禁止携带 `.json`/`.xml` 等表示请求内容类型的后缀（用 accept 头表达）。
- 请求方法：GET 取出资源、POST 新建资源、PUT 更新资源、DELETE 删除资源。
- 请求内容：URL 带的参数必须无敏感信息或符合安全要求；body 带参数时必须设置 Content-Type。

### 【强制】列表类接口返回为空时，返回空数组 [] 或空集合 {}，减少前端琐碎的 null 判断

### 【强制】服务端发生错误时，响应必须包含 HTTP 状态码、errorCode、errorMessage、用户提示信息四部分

说明：四部分涉众分别是浏览器、前端开发、错误排查人员、用户。常见状态码：200 OK、401 未认证、403 拒绝请求、404 资源不存在、500 服务器内部错误。errorMessage 简要描述后端出错原因，注意不含敏感数据；用户提示信息要求简短清晰、友好并引导下一步操作。

### 【强制】JSON 数据所有 key 必须为小写字母开始的 lowerCamelCase 风格

正例：`errorCode` / `menuList`；反例：`ERRORCODE` / `error_message` / `ErrorMessage`。

### 【强制】超大整数场景服务端一律使用 String 返回，禁止使用 Long

说明：JS 的 Number 为双精度浮点，Long 值超过 2^53（9007199254740992）转 Number 会有精度损失。反例：`orderId: 362909601374617692` 前端拿到 362909601374617660，前后端单据不一致。

### 【强制】HTTP 请求 URL 传参不超过 2048 字节；body 传内容必须控制长度（nginx 默认 1MB、tomcat 默认 2MB），超出后端解析会出错

### 【强制】翻页场景：用户输入页码小于 1 时前端返回第一页；后端发现参数大于总页数，直接返回最后一页

### 【强制】服务器内部重定向必须使用 forward；外部重定向地址必须使用 URL 统一代理模块生成，否则线上 HTTPS 会被浏览器提示"不安全"

### 【强制】errorMessage 是前后端错误追踪机制的体现，可在前端 hidden 文字类控件或客户端日志中输出，帮助快速定位问题

### 【推荐】服务端返回信息必须标记是否可缓存（如 `Cache-Control: s-maxage=<秒>`）；返回数据使用 JSON 而非 XML；前后端时间格式统一为 "yyyy-MM-dd HH:mm:ss"，统一为 GMT

### 【参考】接口路径中不要加版本号，版本控制在 HTTP 头信息中体现，有利于向前兼容
