## 二、代码格式

> 来源：Google Python 风格指南（中文版）「Python风格规范」（分号/行宽/括号/缩进/序列的尾部/Shebang行/语句/函数长度/主程序）；PEP 8（中文版）「代码布局 / 表达式和语句中的空白符 / 何时使用尾随逗号」。

### 缩进：4 个空格，禁止制表符混用

用 4 个空格作为缩进，不要使用制表符（Google）。空格是首选的缩进方法；制表符应仅用于与已用制表符缩进的代码保持一致；Python 禁止混合使用制表符和空格进行缩进（PEP 8）。

### 续行：垂直对齐或悬挂缩进

续行应使用括号、方括号和大括号内隐式行连接垂直对齐换行元素，或使用悬挂缩进。使用悬挂缩进时：第一行不应有任何参数，并应使用进一步的缩进以清楚区分为续行。Google 规定：添加 4 个空格的悬挂缩进（禁止 2 个空格的悬挂缩进）；右括号可以置于表达式结尾或者另起一行，另起一行时右括号应与左括号所在那行的缩进相同。

多行结构的闭合括号/方括号/圆括号可以与列表最后一行的第一个非空白字符对齐，也可以与开始多行结构的行的第一个字符对齐（PEP 8）。

`if` 条件部分需要写成多行时，本 PEP 没有明确规定如何（或是否）进一步视觉区分条件续行与嵌套套件；可接受的选项包括：不额外缩进、加一行注释借助语法高亮区分、在条件续行上加额外缩进。

### 行宽

- Google：最大行宽 80 个字符。例外：长的导入语句、注释里的 URL/路径名/长的标志、不便于换行且不含空格的模块级长字符串常量、Pylint 禁用注释。如果一行超过 80 且 Black 或 Pyink 无法继续缩减行宽则允许超限，但鼓励按规则手动拆分。
- PEP 8：所有行限制为最多 79 个字符；文档字符串或注释等结构限制较少的长文本块限制为 72 个字符。仅由一个团队维护的代码，团队达成一致时行长可增到 99 个字符，但注释和文档字符串仍应在 72 个字符处换行。Python 标准库保守地要求 79（注释/文档字符串 72）。

不要用反斜杠表示显式续行，应该利用圆括号、中括号和花括号的隐式续行；如有需要，可以在表达式外围添加一对括号。反斜杠仍合适的情况：Python 3.10 之前无法使用隐式连续的多行 `with` 语句、`assert` 语句。确保适当缩进续行。

最好在最外层的语法结构上分行；需要多次换行时，应在同一层语法结构上换行。多行链式调用、长字典同理。注释中的长 URL 可以独立成行，不得用反斜杠拆断。

### 二元运算符换行位置

在二元运算符之后换行会使运算符分散在不同列、且每个运算符从其操作数移开，损害可读性。遵循数学（Knuth《计算机与排版》）传统、在二元运算符之前换行通常会产生更具可读性的代码。Python 代码中允许在二元运算符之前或之后换行，只要局部约定一致即可；对新代码，建议采用 Knuth 的风格。

```python
# Wrong: operators sit far away from their operands
income = (gross_wages +
          taxable_interest +
          (dividends - qualified_dividends) -
          ira_deduction -
          student_loan_interest)

# Correct: easy to match operators with operands
income = (gross_wages
          + taxable_interest
          + (dividends - qualified_dividends)
          - ira_deduction
          - student_loan_interest)
```

### 空行

顶级函数和类定义应前后各留两个空行；类中的方法定义前后各留一个空行；额外的空行可以（少量）用于分隔相关函数组，相关的一行代码组之间可以省略空行（例如一组虚拟实现）；在函数中少量使用空行来表示逻辑部分。Python 接受 Control-L（^L）换页符作为空白符，可用于分隔文件相关部分（部分编辑器不识别）。

### 分号与语句

不要在行尾加分号，也不要用分号将两条语句合并到一行。通常每个语句应该独占一行；如果判断语句的主体与判断条件可以挤进一行，可以放在同一行——但只适用于没有 `else` 的 `if`，不适用于 `try`/`except`（`try` 和 `except` 不能放在同一行）。复合语句（同一行上的多个语句）通常不建议使用；带小主体的 `if`/`for`/`while` 同行有时可以，但多子句语句绝不能这样做，也要避免折叠此类长行。

### 括号宁缺毋滥

使用括号时宁缺毋滥。可以把元组括起来，但不强制；不要在返回语句或条件语句中使用括号，除非用于隐式续行或表示元组。反例：`if (x):`、`if not(x):`、`return (foo)`。对包含单个元素的元组，括号比逗号更直观：`onesie = (foo,)`。

### 表达式和语句中的空白符

避免以下多余空白：紧靠括号/方括号/大括号内（`spam( ham[ 1 ], { eggs: 2 } )` 错）；尾随逗号和后面的闭括号之间（`bar = (0, )` 错）；紧靠逗号、分号或冒号之前。但切片中的冒号充当二元运算符（视为优先级最低），两侧应有等量空格，扩展切片两个冒号间距相同，切片参数省略时空格也省略：`ham[lower + offset : upper + offset]` 对、`ham[lower + offset:upper + offset]` 错。紧靠函数调用参数列表或索引/切片的开括号之前不加空格（`spam (1)`、`dct ['key']` 错）；不要为了对齐在赋值等号周围加多个空格。

- 避免在任何地方留下尾随空白：反斜杠后跟空格和换行不计为行延续标记；许多项目有预提交钩子拒绝它。
- 始终在这些二元运算符两侧各留一个空格：赋值（`=`）、增广赋值（`+=` 等）、比较（`==`、`<`、`>`、`!=`、`<=`、`>=`、`in`、`not in`、`is`、`is not`）、布尔（`and`、`or`、`not`）。
- 使用不同优先级运算符时，可考虑在优先级最低的运算符周围加空格，自行判断；但不要使用超过一个空格，二元运算符两侧空白数量保持相同。`x = x*2 - 1`、`hypot2 = x*x + y*y` 正确，`x = x * 2 - 1` 错误。
- 函数注解应使用冒号的常规规则，如果存在 `->` 箭头，其周围应始终有空格。
- `=` 用于指示关键字参数或未注解函数参数的默认值时，`=` 两侧不用空格（`def complex(real, imag=0.0)`）；当参数注解与默认值结合使用时，`=` 两侧用空格（`def munge(sep: AnyStr = None)`）。

### 尾随逗号

- Google：仅当 `]`、`)`、`}` 和最后一个元素不在同一行时，推荐在序列尾部添加逗号；自动格式化工具会把尾部逗号视为一种格式提示。
- PEP 8：创建单元素元组时尾随逗号是强制的，建议用括号将其括起（`FILES = ('setup.cfg',)` 正确，`FILES = 'setup.cfg',` 错误）。当预期值列表、参数或导入项会随时间扩展（版本控制场景）时，多余的尾随逗号很有用：每个值单独占一行、始终添加尾随逗号、闭合括号放下一行；与闭合分隔符同一行使用尾随逗号没有意义（`FILES = ['setup.cfg', 'tox.ini',]` 错）。

### 源文件编码

核心 Python 发行版中的代码应始终使用 UTF-8，并且不应有编码声明。标准库中非 UTF-8 编码仅用于测试目的；少量使用非 ASCII 字符，最好只用于表示地点和人名，避免使用嘈杂的 Unicode 字符和字节顺序标记。标准库所有标识符必须使用纯 ASCII，可行时采用英语单词（允许缩写和技术术语）。鼓励面向全球受众的开源项目采用类似政策。

### Shebang 行

大部分 `.py` 文件不必以 `#!` 开始。可根据 PEP-394，在需要直接运行的程序主文件开头添加 `#!/usr/bin/env python3`（以支持 virtualenv）或 `#!/usr/bin/python3`。内核通过这行找到 Python 解释器，但解释器导入模块时会忽略这行；它仅对需要直接运行的文件有效。

### 函数长度

函数应该小巧且专一。长函数有时是合理的，因此不硬性限制长度；但若一个函数超过 40 行，应该考虑在不破坏程序结构的前提下拆分。即使长函数现在没有问题，几个月后别人添加新效果时容易出现隐蔽的错误。发现函数难以使用、存在难以调试的错误，或想在不同场景使用其片段时，勇于把它拆分成更小、更容易管理的片段。

### 主程序

提供给 `pydoc` 和单元测试的模块必须是可导入的。如果文件是可执行文件，其主要功能应该位于 `main()` 函数中，并在执行主程序前检查 `if __name__ == '__main__'`，这样导入模块时不会执行主程序。使用 absl 时调用 `app.run(main)`：

```python
def main(argv):
    ...

if __name__ == '__main__':
    app.run(main)
```

否则使用 `def main(): ...` + `if __name__ == '__main__': main()`。导入模块时会执行该模块的所有顶级代码；顶级代码中不能有 `pydoc` 不该执行的操作（如调用函数、创建对象）。

### 【参考】格式化工具

许多团队采用 Black 和 Pyink 作为自动格式化工具，以避免格式上的争论。Google 提供 Vim 配置文件 `google_python_style.vim`，Emacs 用户保持默认设置即可。
