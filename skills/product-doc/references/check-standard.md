# 质量标准（Quality Standards）

> 用于评审产品需求说明书（PRD）是否完整、可追溯、可验证，且符合最新的 product-doc-template.md。本文档是评审 Checklist，不替代模板。

## 适用场景

- 评审由文字、图片、文档、原型、流程图、会议纪要或其他产品资料生成的 PRD；
- product-doc Skill 生成后的自检与独立评审；
- 产品、研发、测试、数据和运营共同确认需求前的把关。

## 评审结论

> 状态与严重度枚举、Finding 字段、轮次边界的唯一事实源是 [product-review-contract.md](product-review-contract.md)。本节只保留人工可读的三档措词，下表是对契约《人工评审结论映射》的镜像，不得在此新增其他结论值。

人工结论只能是以下三种之一，并按固定映射提交机器状态：

- **通过**（→ `APPROVE`）：模板结构完整，产品事实有来源，目标、范围、用户、功能、指标和验收一致，适用条件已覆盖，没有阻塞性信息缺口。
- **需补充**（→ `APPROVE_WITH_FOLLOW_UPS`）：结构基本完整、文档可交付，但输入资料不足、图片不可辨认、指标口径未定、规则存在冲突或负责人和期限未确认；每个缺口必须落为 Q/RISK/DEP 编号。此结果不等于需求已确认。
- **不通过**（→ `REQUEST_CHANGES`；评审封套本身不完整或稿件指纹过期时为 `BLOCKED`）：缺少必填章节或关键内容，存在事实冲突、范围不清、不可验证目标、功能与验收不一致，或把推断内容当成已确认信息。

机械可判定的部分不靠打勾：模板结构、编号追踪、来源台账覆盖、占位符残留、变更历史与评审回执由 `scripts/validate_prd.py` 判定；轮次、视角路由、稿件指纹与 Finding 闭环由 `scripts/review_state.py` 判定。两个脚本未同时返回 0 时，无论人工结论如何都不得写“已确认”。

## 信息完整性与缺口

- [ ] 每份输入都登记了来源、类型、名称或链接、版本/日期和读取状态。
- [ ] 每份输入都有落盘路径和 sha256 内容摘要；用户直接粘贴的文本与截图已先写入 `<feature-directory>/inputs/SRC-XXX.*`，没有“用户提供的文本”这类无指纹条目。
- [ ] 需要专门读取能力（PDF、表格、Lark 文档）而无法读取的资料已记为 `能力不可用` 并进入 `unreadable_or_unavailable`；它承载必填信息时 `input_status` 为 `BLOCKED`，没有由模型按“常见做法”补齐。
- [ ] 文字资料已完整读取；图片逐张查看并记录可辨认内容，模糊、遮挡或无法确认的部分已标记而非补写。
- [ ] 资料中的手机号、证件号、地址、密钥、真实账号等敏感信息只在台账登记“出现过该类字段”与原字段名，真实值未出现在台账、PRD 或评审意见中；第 5 章与 6.1 已写明这类字段的展示、日志与上报边界。
- [ ] 每个关键事实都有来源，或明确标注为可推导/待确认；冲突已保留双方并进入 9.2 决策与待决问题（Q 编号）。
- [ ] 资料缺失没有被写成“不涉及”；只有明确不适用时才使用该表述。
- [ ] 输入不足时标题下有醒目的“信息不完整”提示，缺口同步记录到 2.4 前提与依赖、8.2 依赖与风险、9.2 决策与待决问题和 PRD 自检与确认。
- [ ] 每个 Q 都有影响说明、负责人、截止日期和当前状态；关键缺口未解决时结论不写“已确认”。

## 模板结构与裁剪

- [ ] 输出是产品需求说明书，没有写成技术方案、测试方案或发布方案。
- [ ] 主章节齐全且顺序为：文档信息、背景与目标、用户与使用场景、功能需求、非功能要求、数据埋点与监控、验收标准、发布/依赖/风险、附录、变更历史、PRD 自检与确认。
- [ ] 必填章节都有实质内容；条件章节不适用时保留章节并说明原因，没有被删除。
- [ ] 标题、层级、表头、编号前缀（OBJ/KPI/SC/FR/BR/AF/ST/UI/F/EVT/EXP/AC/DEP/RISK/Q/DEC）和状态枚举与模板一致。
- [ ] 需求规模 S/M/L 的判断依据来自模板《文档裁剪》表（唯一事实源），并写入 1.1 基本信息行（形如 `S / P0`）；条件章节的取舍与该规模匹配；无法判断时按较高一级检查。
- [ ] 9.3 来源与追踪台账任何规模均为必填：正文中每个正式需求编号至少有一行支撑（`SRC-XXX`、定位、可信度、推导依据），台账行不得指向正文中不存在的编号（幽灵行）。
- [ ] `<PYTHON> "$SKILL_DIR/scripts/validate_prd.py" <feature-directory>/product-doc.md` 返回 0。
- [ ] 模板示例、示例编号、示例文案和示例事件已全部替换或删除。

## 文档信息与变更（第 1 章）

- [ ] 需求名称、编号、版本、状态、规模、优先级、负责人、关联工单和目标版本完整。
- [ ] 变更记录含版本、日期、修改人、变更类型、内容和受影响编号及确认人。
- [ ] 需求变更时 `【修改】/【新增】/【删除】` 三类醒目展示，无变化的类别写“无”；修改保留原编号、新增使用新编号、删除项标记已删除且不再作为当前有效需求。
- [ ] 已在“变更历史”只追加上一版快照行和本轮台账，未覆盖、删除或重排历史记录；新需求只保留“无历史版本”一行。
- [ ] 快照外置：上一版正文写入 `<feature-directory>/history/product-doc-v<版本>.md`，台账行登记快照路径与 sha256 摘要；同一“版本 + 内容摘要”的行未被重复追加；上一版全文未被内嵌进 `product-doc.md`（变更历史区不得出现代码围栏）。
- [ ] 最新输入已覆盖旧冲突，未把旧版本方案当作当前事实。

## 背景、目标与指标（第 2 章）

- [ ] 说明了现状、用户问题、影响规模、业务机会和为什么现在做，关键判断有证据链接。
- [ ] 目标描述业务或用户结果，没有把实现方式当目标。
- [ ] 每个 KPI 都有类型、计算口径（分子、分母、去重、排除项）、基线及日期、目标值、统计周期、数据源和负责人；缺失项已列为 Q 而不是用模糊词代替。
- [ ] 每个目标至少有一个结果指标和一个护栏指标，护栏指标说明防止被伤害的整体体验或风险。
- [ ] 本次范围、非目标和后续版本归属清晰，P1 顺延和 P2 排除项都落在非目标中。
- [ ] 前提、技术约束和外部依赖都有状态、不成立时的影响、编号、负责人和确认期限。

## 用户与场景（第 3 章）

- [ ] 场景覆盖真实使用情况，含触发条件、用户目标、期望结果、频次与峰值和失败影响。
- [ ] 画像聚焦目标、动机、行为、痛点、设备环境，没有无关人口标签或可识别个人身份的信息。
- [ ] 每个角色的可查看数据、可执行操作、明确不允许的操作、数据范围和授权来源清晰，与 4.3 功能和 7.1 验收一致。

## 功能、规则与页面（第 4 章）

- [ ] 功能清单覆盖全部本次范围，每项有稳定编号、说明、优先级、关联目标、负责人和关联验收。
- [ ] 4.1 的“关联验收”列未被删除，且每个 P0 功能至少指向 7.1 中的一个 AC 编号；确实无验收时保留该列写“待补充”并在 9.2 建 Q 编号。
- [ ] 存量功能说明了现状流程、痛点和变化点；全新功能说明了“现状不涉及”的原因。
- [ ] 业务流程覆盖权限判断、校验、确认、成功、可重试失败和不可重试失败。
- [ ] 每个功能写清前置条件、触发方式、完成条件、主流程和不可逆影响；涉及资金、删除、对外发送等已单独标注。
- [ ] 业务规则有适用条件、明确表述和冲突时的优先级与示例，且与流程、字段和状态不矛盾。
- [ ] 所有字段都有类型、必填性、默认值、长度或范围、空值语义、可编辑条件、脱敏权限和错误提示。
- [ ] 有生命周期的对象已定义状态、进入条件、允许操作、迁移和终态重复操作行为；界面状态未混入业务状态。
- [ ] 异常与边界覆盖适用的超时与依赖不可用、重复提交、并发修改、权限中途失效和数据被他人修改，并明确输入是否保留、能否重试、是否产生重复业务结果。
- [ ] 页面清单与原型链接可访问并标注版本或日期；页面状态覆盖加载、空数据、校验错误、提交中、失败和无权限；返回、取消和失败恢复行为明确；不同终端差异已说明。
- [ ] 图片无法确认的交互或原型内容没有被写成已确认需求。

## 非功能要求（第 5 章）

- [ ] 性能与容量有可感知指标、统计口径（终端、网络、P95/P99）、预期流量与峰值系数和目标值。
- [ ] 可用性与降级含最大可接受中断、RPO/RTO、降级时用户看到什么和替代路径。
- [ ] 安全与隐私覆盖认证授权边界、敏感数据分类与最小采集、明确禁止的展示/日志/上报行为、防滥用、审计记录、保存期限与删除导出。
- [ ] 涉及个人信息、资金、账号、交易、未成年人或跨境数据时，已有业务与法务负责人的明确结论。
- [ ] 兼容性含支持范围、最低版本、不支持范围、存量数据与外部调用方的迁移边界。
- [ ] 适用时已说明本地化（语言、时区、货币、数字格式）与可访问性（键盘焦点、对比度、替代文本）要求，或注明不涉及及原因。
- [ ] 未指定线程池、缓存、数据库索引等技术实现方式，只描述可测量的质量目标。

## 埋点、监控与验收（第 6、7 章）

- [ ] 事件命名稳定、低基数且表达已发生的业务事实，触发时机精确到界面成功展示、有效点击或服务端最终结果。
- [ ] 每个事件有必填属性及类型、枚举和空值语义、去重依据、上报端、敏感信息边界和负责人；跨端或重试操作定义了关联标识。
- [ ] 不采集密码、令牌、完整证件号、支付凭据和自由输入正文；用户与设备标识的采集有制度依据。
- [ ] 每个目标和关键指标都能追溯到所需事件、维度、口径、看板和告警；漏斗定义了步骤、窗口和排除项。
- [ ] 看板有基线和下钻维度；告警有触发条件、持续时间、最小样本、级别、影响和接收团队；数据质量有覆盖率、延迟和重复率检查。
- [ ] 涉及 A/B 实验时已固定假设、分流单位与比例、主指标、护栏指标、最小样本与周期和停止规则。
- [ ] 每个 P0 功能至少有一条正常验收标准，并覆盖适用的边界、异常、权限、状态、并发和兼容性场景。
- [ ] 验收标准描述用户或外部系统可观察的结果，不依赖表名、类名或内部方法，且关联需求编号可追溯。
- [ ] 验收安排、环境与账号数据准备方式明确，未通过项有负责人、期限和重新确认方式。
- [ ] 上线前确认条件完整：P0 验收通过且无阻塞项、埋点与指标已验证、安全与隐私有结论、帮助与客服口径已准备、遗留项已登记。
- [ ] 文档中未记录真实密码、令牌或敏感数据。

## 发布、依赖与附录（第 8、9 章）

- [ ] 发布与放量含面向范围、观察指标、放量与回滚条件、时间和负责人；存量变更说明了用户感知变化与旧数据保留期。
- [ ] 每个 DEP 有交付项、影响与阻塞范围、负责人和状态；每个 RISK 有可能性与影响、预防措施、可观察触发信号、应对方案和状态。
- [ ] 术语与参考文档、决策记录和待决问题按适用情况填写；每个 DEC 有依据和影响范围。
- [ ] 9.3 来源与追踪台账逐行可回查：资料编号 `SRC-XXX` 只在台账定义，未读取或不可辨认的资料也建行并在状态列写“未读取”；冲突行可信度写“待确认”并指向 9.2 的 Q 编号。
- [ ] 未解决的冲突、依赖和风险都通过 Q/DEP/RISK/DEC 编号追踪，没有隐藏在正文里。

## PRD 自检与确认

- [ ] 章节完整保留，每个结论都有证据或说明，不只是打勾。
- [ ] “不涉及”的项有原因；资料不足时没有被错误标为“不涉及”。
- [ ] 自检结论与 Q/DEP/RISK 编号一致，阻塞项和遗留项已列出负责人与期限。
- [ ] 签署人与实际信息完整性一致；存在未闭环阻塞项、自检有“不通过”项或阻塞项与遗留项非空时，结论不写“已确认”。
- [ ] 独立评审意见原样追加在文档末尾，未被修改、删减或覆盖；每份回执保留 `review_id`、`perspective`、`review_round` 与稿件摘要，且 `review_id` 已登记在 `prd-review.json`。
- [ ] `<PYTHON> "$SKILL_DIR/scripts/review_state.py" verify --state <feature-directory>/prd-review.json` 返回 0；阻塞交付时只能使用 `verify --allow-blocked`，且交付报告不得声称 PRD 已确认。

## 禁止的质量问题

以下任一情况判定为不通过：

- 缺少模板的必填章节、条件章节、表格或编号规范；
- 直接照抄产品资料，没有提炼用户、目标、范围、功能、规则、指标和验收；
- 把图片不可辨认内容、模型推断、示例或占位符写成已确认事实；
- 把资料缺失写成“不涉及”，或把“待确认”写成“已确认”；
- 目标没有可计算指标，功能没有可观察结果，或验收标准无法执行；
- 功能、流程、字段、状态、权限、埋点和验收的编号或名称互相冲突；
- 漏写 P0 功能的异常、边界、权限、状态、并发或兼容性场景；
- 把技术实现、测试步骤或发布操作写成产品需求；
- 信息不全但没有在标题提示、2.4、8.2、9.2 和自检结论中重点说明；
- 需求变更直接覆盖旧 PRD，或遗漏修改/新增/删除分类、旧正文快照和变更追踪；
- 正文出现的需求编号在 9.3 台账无支撑，或台账行指向正文中不存在的编号；
- 把上一版 PRD 全文内嵌进变更历史，或内嵌代码围栏破坏了文档结构；
- 输入台账存在无路径、无 sha256 的条目，或把真实敏感值复制进了台账、PRD 与评审意见；
- 跳过 `validate_prd.py` / `review_state.py` 而声称门禁通过，或脚本返回非 0 后修改台账 JSON 手工放行；
- Reviewer 或 Writer 直接写入 `product-doc.md`（唯一写入方是主 Agent）；
- 涉及资金、资产、隐私、权限或不可逆操作的需求缺少安全、数据生命周期、恢复或用户影响要求。
